# راهنمای معماری و روند توسعه W-CRM

## هدف

این سند مرجع توسعه پروژه است تا ساخت نسخه‌های جدید بدون تخریب Core انجام شود.

## لایه‌ها

```
Presentation
    |
ViewModel
    |
UseCase
    |
Repository
    |
DataSource / Database
```

## Business Profile

Business Profile مسئول تفاوت‌های کسب‌وکار است.

نباید منطق اصلی CRM داخل Profile قرار گیرد.

Profile فقط تعیین می‌کند:

- چه Moduleهایی فعال باشند.
- چه Schemaهایی استفاده شوند.
- چه Theme و Assetهایی نمایش داده شوند.
- داشبورد چه ساختاری داشته باشد.

## App Config

هر برنامه مستقل باید اطلاعات هویتی خود را از Config دریافت کند.

مانند:

- نام برنامه
- لوگو
- آیکون
- نسخه
- تبلیغات
- تنظیمات انتشار

## قوانین کدنویسی

- کامنت‌های فارسی برای بخش‌های مهم اضافه شود.
- از تکرار تنظیمات در فایل‌های مختلف جلوگیری شود.
- حذف فایل بدون بررسی وابستگی ممنوع است.
- تغییرات معماری باید مستند شوند.

## روند ساخت نسخه جدید

1. ایجاد یا انتخاب Profile.
2. فعال کردن Profile مورد نظر.
3. تغییر App Config.
4. بررسی Moduleها.
5. Build و تست.
6. Release با امضای ثابت.
